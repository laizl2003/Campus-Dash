## 3 本期发现并修复的缺陷（4 处）

### 3.1 雪花 ID 超过 JS 安全整数，前端拿到错误 ID
- 现象：发布成功但抢单/详情全挂，报"任务不存在 / ERRAND_NOT_GRABBABLE"；列表页却看着正常
- 根因：雪花 ID ≈2.15e17 超过 `Number.MAX_SAFE_INTEGER`（2^53≈9e15），`JSON.parse` 静默截断
  （实测 215731113107132416 → 215731113107132400）
- 修复：JacksonConfig 全局 long→string 序列化，前端 ID 全程 string
- 教训：long 型 ID 跨语言边界必须想精度；这类错误列表页不报、详情页才炸

### 3.2 RocketMQ 事务消息两个前置条件都没满足
- 现象：settle 走 HTTP 报 500，集成测试却全绿（集成测试关 MQ，走的是 Noop 适配器）
- 根因两层：① Producer 未注册 TransactionChecker，`beginTransaction` 直接抛
  "Transaction checker should not be null"；② topic 建成 NORMAL 类型，事务消息要求
  TRANSACTION 类型，且类型建错无法原地修改，只能 deleteTopic 重建
- 修复：专用 Producer 构建时 setTransactionChecker；init-mq.sh 固化
  `-a +message.type=TRANSACTION`
- 教训：测试关 MQ 验证业务逻辑是对的，但 MQ 真实链路必须单独联调——
  否则"测试全绿"只是 Noop 全绿

### 3.3 两类延迟消息共用 payload 格式
- 现象：自动结算消息消费即 NumberFormatException，MQ 无限重投
- 根因：DeliverErrandUseCase 复用了超时流转的 payload 生成方法，字段布局不同
- 修复：autoSettlePayload 独立定义；extractLong 补空值校验
- 教训：消息格式是生产/消费双方的契约，共用生成方法会在字段顺序等细节埋雷

### 3.4 CORS 只允许 localhost，127.0.0.1 被 403
- 现象：vite 代理转发浏览器 Origin（127.0.0.1:5173）被后端 CORS 拒绝
- 修复：cors-origins 同时配两个
- 教训：CORS 白名单要把用户实际会用的入口都列上

## 4 诚实记录的非阻塞边界

1. "模拟 N 人同时抢"用临时身份（30000+i），无钱包账户，抢中后无法确认接单，
   任务按超时逐轮流转——演示并发没问题，别用临时身份走完生命周期
2. 抢单日志随卡片渲染，单名额任务被抢后卡片离开 PUBLISHED 列表，日志窗口极短
3. S4-a 本轮 TPS≈64（全量测试同跑时），单独跑为 ≈191——同机资源争抢的又一证据，
   数字均只作同机基线
